### All of Us Workspace and Bucket System Organization
Here's how the All of Us infrastructure is organized:
High-Level Architecture
Cloud Platform: Google Cloud Platform (GCP)

Everything runs in Google Cloud Storage buckets in the US-CENTRAL1 region
All compute happens on cloud VMs, not local machines

Storage Layers
1. CDR Bucket (Controlled Data Repository)

Location: gs://fc-aou-datasets-controlled/
Purpose: Centralized, read-only storage for ALL genomic data
Access: "Requester pays" model - your workspace pays for data access
Contents:

Genomic data files (VDS, MT, VCF, PLINK, BGEN)
CRAM files (raw sequencing reads)
Auxiliary data (ancestry TSVs, QC files, manifests)
All by All GWAS results


Key Point: You NEVER copy data FROM here - you read it directly in place
Example paths:

gs://fc-aou-datasets-controlled/v7/wgs/short_read/snpindel/acaf_threshold/hail.mt/ (Hail MT)
gs://fc-aou-datasets-controlled/v7/wgs/short_read/snpindel/aux/ancestry/ (ancestry TSVs)



2. Workspace Bucket (YOUR persistent storage)

Location: gs://fc-secure-[unique-id]/ (auto-created per workspace)
Purpose: Personal project storage area
Characteristics:

Permanent - survives VM deletions
Shared with workspace collaborators
Costs you for storage
If you delete workspace, you delete this bucket


Use for:

Jupyter notebooks (auto-synced)
Analysis outputs
Filtered/processed datasets
Results you want to keep



3. Persistent Disk (YOUR personal VM storage)

Location: Attached to your VM like a USB drive
Purpose: Personal temporary storage across VM sessions
Characteristics:

Private to you (not shared with collaborators)
Survives VM deletions
Costs you for storage even when VM is off
Can be SSD or standard disk


NOT available for Dataproc (Hail) clusters
Use for: Software installations, intermediate files

4. Standard Disk (Ephemeral VM storage)

Location: Part of your VM instance
Characteristics:

DELETED when VM is terminated
No cost when VM is off
Fast local storage


Use for: Truly temporary files during analysis session
